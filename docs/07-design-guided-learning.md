# 设计驱动的 Agent 学习协议（2026-10-10）

> **仅升级 M0–M5 的实践方法，不新增里程碑、不改业务需求、不规定 Commit 数。** 当前主实现语言 Python；Go 留到项目可展示、有可信验收后按实际需求补。执行细则见 [执行手册](04-execution-playbook.md) 和 [防止思考外包协议](06-ai-learning-guardrails.md)。

## 资料分工（不并行刷四门课）

1. **AI Agent Book：原理**。按需求选择一节理论和一个官方实验；聊天内 All-in-One 讲理论、必要的关键代码、逐段解析、练习，标明教学化改写。
2. **Pi 源码：成熟实现对照**。按需读 [pi-mono](https://github.com/badlogic/pi-mono) 中 Agent/Tool 的相应实现，讨论数据结构、状态与错误；若没核实具体版本和文件，不能声称源码已经验证。参考而不照搬。
3. **《软件设计的哲学》：设计评判**。只选当前任务涉及的一个原则（如深模块、信息隐藏、变更放大、认知负担、错误边界、战略编程）；用 [CS190](https://web.stanford.edu/~ouster/cs190-winter24/) 的“独立设计—评审—重构”方式练习；不要求先读完本书或整门课程。
4. **小林 Coding：面试验收**。每次从 [题库映射](05-interview-map.md) 选择相关的 2–4 道已核对原题，提供真实题号与链接；另加项目架构取舍和异常变体追问，改编题须标记。
5. **AgentGuide / Matt Skills / ZCode：工程辅助**。提供工程规范、测试、代码审查；AI 不能替代首次核心机制的设计和个人掌握验收。

## 单次功能的 All-in-One 执行协议

1. **需求**：明确输入、输出、数据契约、权限/停止条件、至少两条失败路径和可执行验收。
2. **原理与对照**：AI Agent Book 讲清机制；Pi 源码说明成熟实现的取舍；聊天直接给必要的代码段/图解/实验，原文未查证时写明。
3. **软件设计**：选一个切题的《软件设计的哲学》原则，解释其适用条件及可能代价，避免过度抽象。
4. **独立设计**：学习者先给接口/状态图、伪代码、至少两个异常分支、替代方案；导师用 CS190 式反例质询复杂性、耦合、职责、可测试性。
5. **Python 实现与验证**：本人先写最小核心链路；ZCode 可辅助脚手架/局部代码；使用 pytest、Mock、必要的真实调用，记录失败与可复现证据。
6. **Code Review 与修改**：检查接口深浅、信息隐藏、变更放大、认知负担、错误边界；指出可证明的问题和取舍，而不是为了应用原则强行重构。
7. **双重验收**：工程门禁看测试/Trace/Commit SHA；学习门禁看解释、闭卷重建、变体、调试、取舍；用小林真题与追问在 T0/T+3/T+14 复核。
8. **归档**：GitHub 放设计决策、代码与可重现实验证据；Notion Day 笔记留作自由记录和自答，面试题放在页末，不预设固定模板。

## 里程碑 × 设计原则

| 阶段 | 重点 | 设计评审问题 |
|---|---|---|
| M0 需求与基线 | 复杂性来源、职责边界 | 哪些业务根本不需要自主 Agent？ |
| M1 Agent Loop / Tools | 深模块、信息隐藏、错误边界 | Schema、参数校验、工具权限各由谁负责？ |
| M2 RAG | 通用/专用抽象 | 检索实现暴露给 Runtime 的细节是否过多？ |
| M3 Web / 研究 | 复杂性、错误处理 | 不可信网页和工具失败如何与决策隔离？ |
| M4 Session / API / SSE | 依赖方向、状态管理 | HTTP、Session、Runtime 的边界在哪里？ |
| M5 Eval / 优化 | 战略编程与重构 | 哪次调整有证据降低了复杂性？ |

## 当前 Tool Calling 课例

**AI Agent Book**：ToolCall / ToolResult 的格式、参数与 ID 关系。**Pi 源码**：查证工具声明、调度和执行的分层。**软件设计**：尝试为 Tool Registry/Executor 设计简单接口，明确未知工具、非法参数、越权、超时；考虑拆得太细可能增加复杂性。**自己实现**：Python 中 Mock 覆盖成功与失败路径。**Code Review**：评审设计取舍。**小林验收**：Function Calling 真题 + 自己的异常变体。

**特别说明**：课程文档变更不表示已完成代码、测试、论文或面试验收；只有真实证据才可更新 progress。

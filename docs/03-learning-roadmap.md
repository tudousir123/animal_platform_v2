# 学习路线｜先 Lab Agent，后 SalesPilot（唯一有效版）

更新时间：2026-10-11。**不是固定天数/Commit 地图**，无需为了遵循旧计划反复改项目。技术主线 Python，Go 后期选学。

## 阶段 A：Lab Agent 1.0.0 —— 唯一当前主线

使用用户已选的 Lab Agent 1.0.0 配套**视频 + 源码**。按视频和实际代码的原有逻辑推进，不另排一套强制开发顺序，也不要求同步创建 SalesPilot 功能。下表是*学习核查点*而非未经阅读项目即宣称存在的实现。

| 核查主题 | 阅读/实践关注点 | 能力输出 |
|---|---|---|
| Python 工程基础 | 模块、依赖、类型标注、异常、async（遇到时补） | 能定位调用关系并解释错误 |
| FastAPI | API 入参、路由、依赖、异步与测试 | 能追踪一条请求从 HTTP 到业务逻辑 |
| Agent / Tools | 模型调用、ToolCall / ToolResult、状态流和失败终止 | 能讲清一次 Agent 执行过程 |
| LangGraph（如项目使用） | State、Node、Edge 和实际执行路径 | 能根据源码解释工作流而非只背概念 |
| RAG | 数据处理、Embedding、检索与引用 | 能解释检索结果如何影响答案 |
| MySQL / 持久化 | 表与模型、读写与状态数据 | 能找出数据写入和读取位置 |
| SSE / 流式 | 流事件、错误处理与客户端响应 | 能解释数据如何逐步发送 |
| 基础工程素养 | 配置、日志、测试、调试、结构组织 | 能定位问题、重现实验并做小幅修改 |

### 每个视频/模块的闭环

1. 看视频并记录本节要解决的问题。
2. 读对应源码、画调用链，指出输入、输出、数据流和错误边界。
3. 不懂的原理只查 **AI Agent Book** 的对应章节；ChatGPT 提供 All-in-One 解释、教学化代码与练习。
4. 跟随复现，尝试预测执行、解释代码、修改一个局部行为或测试一个边界。
5. 做 **小林 Coding** 对应 Python / Agent / RAG / Tools 题目；区分原题与改编题，能够联系本模块代码说明。
6. 在 Notion 自由写笔记/思考/问题，GitHub 仅记录真实验证或自身获得授权的代码。

**阶段 A 验收**：完成选定 Lab Agent 视频和源码学习；能独立说明主要架构、核心调用链与错误边界；能够复现关键运行路径、修改一处有代表性的模块，并通过自己解释与面试追问来验证。测试、运行、掌握三个状态分开记录，未测就是未测。

**当前下一步**：继续按 Lab Agent 配套视频往下学，整理源码笔记。不安排第二个项目、不额外规划大量 Commit，也不强制先写完整系统架构。

## 阶段 B：SalesPilot 工程化迁移 —— 阶段 A 结束后启动

将 Lab Agent 学到的 Python / FastAPI、Agent、RAG、MySQL、SSE 和可靠性原则迁移到新能源汽车销售场景。按真实需求独立确定业务范围与架构，ZCode 辅助工程实现、本人负责设计判断。参考业务仓库：[FelixDemon1/SalesPilot](https://github.com/FelixDemon1/SalesPilot)。[此前产品规格](01-product-spec.md)是**待复审候选需求**，不等于现在就要实现或未来业务形态已锁死。

沿用此前 M0–M5 **六个能力验收节点，仅在阶段 B 启动后使用**：

| 验收节点 | 对应能力（未来规划，均未验收） |
|---|---|
| M0 | 需求、案例、运行环境与 baseline |
| M1 | Model + Tool Calling + Agent Loop 的最小端到端链路 |
| M2 | 企业知识库 RAG 与可信引用 |
| M3 | Web Search 与有界研究 / 外部证据 |
| M4 | FastAPI、Session、SSE、持久化和可靠性 |
| M5 | Eval、Trace、调试优化、部署展示与面试作品 |

每个阶段依真实需求选择足够简单的技术和测试；不规定 Commit 数、框架数量或完成天数。原文档中的具体题号及业务用例可分别在 [面经索引](05-interview-map.md) 和 [产品规格](01-product-spec.md) 查阅，但**不再驱动阶段 A**。

# 产品规格：SalesPilot Learning Edition

> **状态（2026-10-11）**：此文是 **Lab Agent 1.0.0 学完以后**启动 SalesPilot 迁移时复审的候选业务规格，**不是当前开发任务或已冻结的最终业务形态**。现在唯一实践主线为 Lab Agent 配套视频/源码；未来再根据实际需求确定销售培训、知识问答等功能边界。当前路线见 [学习路线](03-learning-roadmap.md)。

> 需求先于框架。2026-10-10 审查版；以下均为待实现需求，不是已完成功能。

## 用户与真实任务

目标用户：新能源汽车销售顾问；在接待客户前或现场，需要快速核对车型配置、内部产品手册、竞品公开信息及相关政策，整理有据可查的答复。

**区分两条业务流**：

- **普通问答（固定 Workflow）**：问题 → 识别资料来源 → 内部 RAG / 可选 Web Search → 根据来源生成回答与引用。不是每次都启动自主 Agent。
- **深度研究（有界 Agent）**：用户问“我们的演示车型与某真实竞品在续航、安全、价格上的优劣，最近是否有新政策？” → Plan → 有权限的工具调用 → 观察结果 → 判断证据缺口 → 必要时补查 → 有引用的答复。工具、观察与任务结束由宿主代码执行并验证。

## 模拟演示资料

教学阶段可以使用**虚构的“星辰电动 ES9”**和自己制作的车型手册。所有数字只在演示文档中出现并标为模拟值，所有真实市场、价格和政策说法必须保留链接和日期。不存在来源时回答「资料不足」，不可由模型常识代替车型规格事实。

**初期业务工具**：

- `search_local_docs(query)`：内部文档检索，返回 document_id、引用片段、版本与位置。
- `search_web(query)`：公开网页结果，返回 URL、标题、抓取时间；真实网络需要服务凭据，Mock 必须明确标识。
- 可选 `lookup_demo_vehicle(model)`：只读结构化演示车型规格，给最小 Loop 提供稳定可验证的工具结果。

系统对客户购买决策提供信息与比较，不自动报价成交、不对外承诺库存、优惠或政策待遇。

## 从最小可运行到可交付

1. **最小纵向演示（M1）**：CLI 问一句话 → 模型选择一个模拟车型工具 → 本地程序执行 → 将真实结果交还模型 → 给答案；无网络的 Mock 路径可重现。
2. **资料事实层（M2）**：上传/导入自制手册；检索、召回、引用并测量。
3. **研究链路（M3）**：本地 RAG 与网页 Search，支持多工具、检索补查和信息冲突标注。
4. **服务层（M4）**：FastAPI / HTTP / 流式 SSE，Session 持久化；先 SQLite 或轻量文件库。
5. **可靠交付（M5）**：评测报告、失败归因、优化对照、简历 V1、可演示代码。

FastAPI 的最小 `GET /health` 和 `POST /chat` **可在 M1 提前接通**；M4 才补 Session、SSE、并发与部署。

## 参考 API（最终设计由实际接口验收确定）

```text
GET  /health                       # 服务状态
POST /chat                         # 问答/可指定 mock provider
POST /research                     # 有界多工具研究
POST /sessions                     # 创建会话
GET  /sessions/{id}                # 会话历史
POST /sessions/{id}/messages       # 多轮问答
POST /sessions/{id}/stream         # SSE 输出（也可合并进 messages）
```

业务逻辑不得直接绑定 FastAPI。模型提供商、搜索服务、检索器、存储使用可替换接口。

## 最初需求用例（是测试计划，不是通过数据）

| 编号 | 用户提问/情境 | 期望系统行为 |
|---|---|---|
| B01 | “演示 ES9 的续航是多少？” | 调用演示车型或内网检索，引用文档或数据字段 |
| B02 | “这款车有几种配置？” | 只回答文档中出现的配置，注明资料版本 |
| B03 | “最新版 Model Y 价格是多少？” | 不用虚构价格；若 Web 不可用则明确不能实时核实 |
| B04 | “ES9 和 Model Y 的续航哪个更强？” | 拆分不同来源、单位与测试工况；证据不足不硬排序 |
| B05 | “现在购车有最新补贴吗？” | 使用日期/地区限定的官方来源；不能保证政策资格 |
| B06 | “随便说一个没有的 ES9 电池容量” | 不编造，明确演示资料缺失 |
| B07 | 工具不存在/参数类型错误 | 程序级校验并记录错误，不执行任意函数 |
| B08 | Search 超时/返回空 | 有界失败/降级，不能伪造搜索结果 |
| B09 | 注入网页要求泄露环境变量 | 不遵从网页指令、拒绝未授权工具 |
| B10 | 连续两轮需要补充检索 | 保留 tool_call 与 observation 顺序，有限补查、稳定终止 |
| B11 | 同一 Session 多轮追问 | 保留对应用户会话；不会读到其他人的内容 |
| B12 | SSE 客户端中途取消 | 清理调用资源、有明确结束状态，日志不含密钥 |

Golden Cases 初始由 B01–B12 演化，必须补充实际输入、fixture、期望动作、测试方法与结果。

## 必须明确的不做事项

MVP 不强制 LangGraph、Django、Multi-Agent、GraphRAG、OCR 布局分析、ES、PostgreSQL、Redis、全套 React 前端、复杂登录、分布式队列、RL 或训练/微调。需要引入时写 ADR、说明对应可测瓶颈与额外成本；不为了简历堆组件。

## 提前定义的风险

- 私有企业资料不能上传第三方模型服务，未经授权的客户数据不保存。
- 真实购车政策、车型数据可能过期；将知识来源、版本、时间和置信边界放在返回结果中。
- Prompt 注入与工具调用必须由应用代码设置权限边界。
- 模型选择工具成功不等于工具已执行；必须基于真实 ToolResult 评价任务成功。
